# Formal Delivery Gate

Use this gate before producing, sending, submitting, or calling complete a
formal knowledge deliverable: report, essay, proposal, deck, technical brief,
capstone, assignment, client document, or research artifact.

## Gate

1. Intake the brief:
   - audience
   - deadline
   - deliverable type
   - word/page count
   - required format
   - rubric or acceptance criteria
   - required sources or evidence
   - final file/export requirements
2. Scope the work:
   - essay
   - report
   - problem set
   - presentation/deck
   - proposal
   - technical brief
   - client deliverable
3. Research with local retrieval first and external/current sources when
   required.
4. Draft V1 as a working draft only.
5. Run a red-team review before delivery.
6. Revise accepted findings and reject invalid criticisms explicitly.
7. Compile the requested format, references, appendices, tables, and export.
8. Verify the exit gate before delivery.

## Red Flags

- delivering V1
- drafting before reading the brief
- treating a rubric as optional
- missing citation or evidence requirements
- wall-of-text paragraphs in a formal document
- over word count without compaction
- relying on clean prose while missing the actual acceptance criteria
- formatting afterthoughts that break the submission/export requirement

## Kira Boundary

Generated delivery plans live under `formal-deliverables/` and are ignored by
Git. This gate helps plan and verify formal outputs; it does not submit,
publish, send, or file anything unless Stephen explicitly asks for that action.
