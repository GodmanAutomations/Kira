# Brand Foundations

Use this skill when a project needs a clear public identity before names,
copy, visuals, product pages, or outreach harden into default choices.

## Contract

- Extract the brand shape before producing public-facing assets.
- Keep brand work grounded in real audience, real enemy, real value, and real
  proof.
- Prefer plain positioning over vibes-only adjectives.
- Separate identity decisions from unfinished creative options.
- Do not invent a visual system that conflicts with existing project identity.
- Record open questions instead of hiding uncertainty in polished language.

## Default Flow

1. Name the brand, product, or project.
2. Define purpose and the core enemy.
3. Define target audience with psychographics before demographics.
4. Choose voice and archetype.
5. State value proposition and proof.
6. Define visual direction: colors, type feel, density, and avoid-list.
7. Capture do/don't rules and next slice.

## Output Shape

Create a compact `brand_guidelines.md` style guide with:

- brand
- purpose and enemy
- audience
- voice and archetype
- value proposition
- proof
- visual direction
- do/don't rules
- open questions
- next slice

## Helper

Use `bin/athena-coding-anchor-brand "<brand>"` to create a local brand guide
template. Generated brand guides live under `brand-guides/` and are ignored by
Git unless Stephen deliberately promotes one.
